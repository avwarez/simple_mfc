# Cases whose VALUE is a platform fact rather than a behaviour, and which
# therefore cannot be compared between a recording made on Windows and a
# POSIX build. Every entry needs a reason.
#
# This list applies ONLY to the cross-platform comparison
# (conformance_vs_recorded_real_mfc). The side-by-side Windows comparison
# — native and real MFC on the same machine — uses no exclusions at all:
# there, every difference is a real difference.
#
# compare.py fails on a stale entry, one naming a case that no longer
# exists on either side, so this list cannot quietly outlive what it
# describes.
#
# NOT a place for "this fails and I don't know why". A case that differs
# for any reason other than the platform's own naming of things is a
# conformance bug and belongs in the failure report, not here.

# --- Temporary-directory paths -------------------------------------------
# GetTempPath() is C:\Users\RUNNER~1\AppData\Local\Temp\ on the Windows
# runner and /tmp/ here. The methods under test return the path they were
# given, so what is compared would be the OS's temp location, not MFC.
# CFileFind.Single.GetRoot additionally carries the separator, which is the
# other half of the same fact.
CFile.GetFilePath
CFileFind.Single.GetFilePath
CFileFind.Single.GetRoot

# --- The DOS/Windows "archive" file attribute ----------------------------
# Windows sets FILE_ATTRIBUTE_ARCHIVE on any newly written file; POSIX has
# no such bit and CFileFind::IsArchived answers FALSE there. What differs
# is the filesystem's own bookkeeping, not the method.
CFileFind.Attr.IsArchived

# --- The ANSI code page --------------------------------------------------
# _AtlGetConversionACP answers CP_THREAD_ACP (3) on Windows, where a thread
# locale exists to prefer over the system one. Off Windows there is neither
# an ANSI code page nor a thread locale, and it answers CP_ACP (0). The
# value IS compared side-by-side on Windows, which is where it means
# something.
AtlGetConversionACP.value
